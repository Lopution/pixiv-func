# 修复移动端 UI 动画与个人页问题

## Goal

修复真实手机无代理使用中发现的四类 UI 缺陷：跨页面作品图片误触发 Hero 飞行、首次进入作品详情时内容/作者头像晚于转场出现、简介需要额外点击才显示，以及个人资料页重复提供设置入口。保持现有右侧滑入/返回节奏，不引入与问题无关的全局动画管理或防御性抽象。

## Background and Confirmed Facts

- `IllustCard` 的图片使用 `Hero(tag: 'IllustHero-<id>')`，同一组件同时用于推荐、排行、新作、搜索和个人资料作品流。
- `UserPage` 的个人资料作品流复用 `IllustCard`。新收藏确认后，同一作品可能同时出现在当前信息流和个人资料收藏流；两个路由上的相同 Hero tag 会让图片参与不相关的个人资料转场。个人资料数据在转场期间才到达时，Hero 目标又会在转场中途出现，表现为误飞或只剩普通滑入。
- `IllustDetailPage` 目前只接收 `illustId`。详情控制器异步请求，首帧只有 `IllustStore` 已有快照时才渲染内容；没有快照时先显示 loading，Hero 目标不存在。详情大图和作者头像也在详情组件创建后才开始请求。
- `lib/features/illust/detail/illust_detail_page.dart` 的 `_InfoBlock` 以 `_showCaption = false` 开始，并通过“简介”区块切换显示；富文本解析已存在，默认状态仍是收起。
- `lib/features/profile/user_page.dart` 在 `onSettings == null` 时创建一个默认的 `SettingsPage` 路由。设置页账户卡片打开 `MePage` 时没有传入回调，因此个人资料页再次出现设置按钮并可重复推入设置页。
- `IllustStore`、`UserStore` 和现有图片缓存是项目内的共享边界；本任务不新增全局缓存、全局 Navigator 或泛化的状态闸门。
- 用户约束：不要写过度的防御性代码；只处理可由当前产品行为和已有边界证明的状态。

## Requirements

### R1. Hero 动画作用域

- 进入/退出作品详情时，来源卡片与首帧详情目标匹配时继续使用现有图片 Hero；无匹配目标时自然使用普通右侧滑入，不制造占位飞行。
- 进入或退出个人资料页时，个人资料作品不能与下方信息流的作品共享 Hero 作用域；新收藏作品不得凭空从其他页面飞入或飞出。
- Hero tag 不得依赖上一次路由、上一次收藏状态或异步请求的晚到结果；重复点击/返回后不残留旧飞行状态。

### R2. 首次详情加载时序

- 从已有作品卡片进入详情时，详情首帧直接使用该作品的现有实体快照，详情结构和作者信息与转场同步出现；详情 API 只负责后台刷新。
- 详情首帧必须存在与来源相同的 Hero 目标，不能先显示 spinner 再在转场结束后插入目标。
- 作者头像和详情图片使用已有 URL/缓存边界，在详情首帧创建对应图片内容；不得把内容渲染推迟到详情请求完成。

### R3. 简介默认展示

- 作品简介不再显示单独的“简介”展开按钮。
- 非空简介默认渲染；现有 HTML 富文本行为（换行、实体解码、站内/站外链接处理）保持不变。
- 空简介不占用额外布局空间。

### R4. 个人资料设置入口

- 从设置页账户卡片进入当前账号资料时，不显示会再次推入 `SettingsPage` 的设置按钮。
- 个人资料页不再显示设置入口；设置页账户卡片进入资料后只保留资料页自身的编辑、分享和内容筛选操作。
- 设置页账户卡片、个人资料页和返回栈只能形成一层设置页，不出现重复跳转。

## Acceptance Criteria

- [x] AC1：信息流作品卡片进入详情时，首帧存在相同作品的 Hero 目标；从信息流进入个人资料时，个人资料作品不触发跨路由 Hero 飞行，返回同样不触发。无目标时只呈现普通滑入/返回。
- [x] AC2：新增首帧回归测试证明传入/共享的作品快照会先渲染详情内容、作者信息和 Hero 目标，再等待详情 API；不以 loading spinner 覆盖已有快照。
- [x] AC3：简介在首帧默认可见，界面不再出现“简介”展开控件；已有富文本解析和链接点击测试继续通过，空简介不渲染内容区。
- [x] AC4：设置页账户卡片打开当前账号资料时找不到设置按钮，且不会在现有设置路由上再推入一层；个人资料页不再接收或渲染 `onSettings`。
- [ ] AC5：`flutter analyze --no-pub`、相关 widget 测试和 `git diff --check` 通过；全量测试仍有两个既有 loopback 超时。
- [ ] AC6：debug APK 已构建；当前 `adb devices -l` 无设备，四条真实手机路径待设备连接后复测。

## Out of Scope

- 重写 `ReplicaPageRoute` 的转场曲线或创建全局动画协调器。
- 为所有页面建立新的预加载/缓存框架，或加入与这四个问题无关的空值兜底、重试闸门和状态复制。
- 修改 Pixiv API、网络路由、登录和下载行为。
- 重新设计个人资料信息架构；本任务只移除重复设置入口并调整简介默认状态。

## Key Decisions

- 个人页作品列表点击进入详情时保留图片 Hero，避免页面之间出现割裂感。实现采用来源作用域：个人页卡片与它打开的详情共享同一作用域，个人页与底层信息流使用不同作用域，从根上避免跨路由误飞。
- 详情首帧优先使用卡片传入的作品快照；不为此引入新的全局预加载框架。详情 API 在后台刷新，图片继续复用现有 `PixivImage`/缓存边界。
- “简介”直接默认展示，个人资料页彻底移除设置入口；不添加隐式兜底行为。
