# 全局交互一致性与页面体验收敛

## Goal

在已归档的 `09-11-ui-redesign` 基础上，把用户跨页面反复使用的操作规则、信息层级与状态表达收敛成可迁移、可验证的一套体验。目标不是让所有页面长得相同，而是让同一种对象和同一种动作在不同页面仍可识别、可预测、可恢复。

- 当前规划基线为 `main@8215fa8`。审查中提到的 PR #48（SnackBar）和 #50（详情元信息排版）均已合并；它们分别解决共享反馈形态及详情元信息的一部分，不代表本任务其余交互问题已解决。

- 审查建议的六段顺序是当前任务地图的默认依据：先修确定错误，再收敛入口与查询上下文，再整理浏览/阅读，随后统一对象条目与管理页，之后处理表单/弹层/跨端布局，最后才调整动效。

## Requirements

### R1 — 先复核、后实施

每个子任务在实现前必须把审查结论对照当时的 `main` 重新定位到代码与测试；已经由 #48、#50 或后续提交解决的项应记录为已吸收或不再适用，不得重复改造。静态审查结论、自动测试、人工视觉检查和真实设备验证分别记录。

### R2 — 明确交互错误优先

优先修复动作名称与实际后果不一致、显式返回无法离页、本地阅读进度不恢复、交互外观没有动作、测试/清除/取消改变了用户未确认状态等确定性问题。修复不得以吞错、空操作或静默降级制造成功。

### R3 — 分类、搜索与主页上下文持续可见

重要能力不得只通过重复点击当前标签或长按进入。新作、排行、搜索、作者页和收藏标签的当前内容类型、范围、筛选与私密/公开上下文应在路径中持续可见，并在跳转、返回和加载状态之间保持一致。

### R4 — 同一种对象保留同一基础识别方式

小说、插画、用户等对象在不同页面共享基础视觉与交互契约；排名、时间、阅读进度、更新状态等是命名明确的场景变体。不得为了统一而抹掉页面任务差异，也不得以固定裁切牺牲插画内容。

### R5 — 浏览、查看与阅读操作可达

多页作品、全屏查看器、系列目录、动图和在线/本地小说应区分“浏览内容”和“操作内容”，同时保持返回、保存/分享、目录/进度、排版和错误状态的入口可达。打开目录或查看更新不得被错误记作已阅读进度。

### R6 — 管理页、输入器与表单状态可预测

历史、稍后再看、追更、本地书库、下载任务、评论输入、资料编辑和设置表单应清楚区分主操作、危险操作、即时生效、待保存草稿、处理中、失败与撤销。键盘、表情/贴图面板和返回优先级必须有单一状态规则。

### R7 — 跨端布局与输入等价

手机、横屏、平板和桌面按任务选择内容宽度与布局；设置/表单/文章不直接拉满宽屏。依赖手势的关键能力必须提供键盘、鼠标或可见控件的等价路径，并保持最小点击区域、大字号、长翻译和减少动效可用。

### R8 — 动效服务于状态，不改变功能

同级分类、头部收起、查询流、详情/查看器转场、表单与加载使用一致且可解释的动效规则。动画期间不得出现可见但不可点击的关键操作；减少动效只移除装饰性位移/缩放，不删除必要反馈。

### R9 — 任务树与集成验收

本父任务保存完整审查来源、子任务边界、依赖顺序和跨子任务一致性验收。实际产品改动由可独立验证的子任务承担；父任务不直接作为实现分支。最终集成复核必须确认不同子任务没有重新引入平行组件、冲突手势或不一致文案。

## Acceptance Criteria

- [ ] 审查中的每一项建议都映射到一个子任务、明确延期项、已由当前 `main` 吸收的提交，或有证据的“不采纳”结论；不存在无归属条目。
- [ ] 确定性交互错误优先关闭，并有针对动作终态、返回优先级、状态恢复和失败可见性的回归测试。
- [ ] 重要分类、搜索条件、作者/收藏范围不再只依赖重复点击或长按，跨页上下文可见且返回后不丢失。
- [ ] 同一种小说/插画/用户对象在推荐、排行、搜索、新作和管理页使用同一基础组件契约，场景差异通过有限、命名明确的变体表达。
- [ ] 多页作品、查看器、系列、动图与在线/本地阅读的主要操作可达；查看状态、更新游标与真实阅读进度不混用。
- [ ] 表单、弹层、下载与评论输入明确区分即时设置、草稿、提交中、成功、失败、取消和危险操作，失败不丢失可恢复输入。
- [ ] 代表性的 320/390/600/840/1200dp、手机横屏、大字号、长翻译、键盘/鼠标、屏幕阅读代表路径、触觉反馈与 reduced-motion 场景通过对应的自动或人工验收；未执行的真机/辅助功能检查明确标注。
- [ ] 每个叶子任务通过其聚焦测试、`flutter analyze --no-pub`、适用的全量测试和 `git diff --check`；父任务最终记录跨任务集成结果。

## Out of Scope

- 不更换 Flutter、Material 3、Riverpod、路由或现有业务数据层。
- 不重做已完成的全局视觉系统，也不新建与现有 `lib/app/widgets/`、`feed/`、主题 token 平行的组件家族。
- 不借 UI 收敛修改 Pixiv API、OAuth/TLS、账号安全、下载持久化或网络策略语义；若交互修复暴露业务缺陷，应单独回到规划。
- 不把所有页面强行改成相同布局，不统一插画裁切比例，也不以动画时长或圆角批量替换冒充体验完成。
- 不在本父任务中直接实现产品代码；每个叶子任务另走分支、测试、PR 与验收。
