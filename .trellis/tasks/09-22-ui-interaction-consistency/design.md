# 全局交互一致性与页面体验收敛：任务设计

## 1. 设计目标

本目录是路线图父任务。它维护 Astra 审查的事实复核、工作包边界、依赖和最终集成验收，不在一个分支中直接修改全部产品代码。

统一对象是可迁移的交互规则，而不是页面外观：

- 同一动作有相同名称、结果、取消和失败语义；
- 同一对象有稳定的基础识别方式，页面用途通过显式变体表达；
- 用户正在看的范围、类型、查询、筛选和阅读位置持续可见且可恢复；
- 手机手势有桌面可见控件、鼠标或键盘等价路径；
- 动画表达状态变化，不改变功能是否可达。

## 2. 事实来源与优先级

1. 本任务 `prd.md` 的行为边界与验收条件。
2. `research/astra-review-traceability.md` 对 `/root/Astra.txt` 的当前 HEAD 复核。
3. 叶子任务启动时的仓库代码、测试与 `main` SHA。
4. `.trellis/spec/frontend/` 的组件、状态、质量和目录规范。
5. 自动测试、桌面/模拟器/真机的实际行为证据。

静态审查不能覆盖运行时证据。若审查建议与当前代码或真实运行冲突，以可复现事实为准，并更新追踪矩阵。

## 3. 父任务与叶子任务规则

- 父任务不运行 `task.py start`，没有产品实现分支。
- 用户确认本规划后，再按工作包创建 planning 状态的叶子任务；创建叶子不等于批准实现。
- 每个叶子必须拥有互不含糊的页面/行为边界、自己的 PRD/design/implement、分支、检查和 PR。
- 同一文件需要分阶段修改时，以依赖顺序串行合并；不让两个并行分支编辑同一文件。
- 叶子过大时按其 `implement.md` stage 拆分分支，命名遵守仓库 `task/<MM-DD-slug>-<stage>` 规则。
- W10 只做集成验收与证据驱动的窄修复，不借最后阶段重写前九个工作包。

## 4. 计划任务地图

### W1 — interaction-outcome-correctness

先关闭静态代码可证明的动作/结果错误：

- 在线阅读器显式返回真正离页，系统返回仍可先关闭临时 chrome；
- 小说标签要么可操作，要么呈现为非交互文本；
- 本地小说持久化位置转换为有效 `initialAnchor`，包含边界/失效处理；
- 搜索热门标签不再为了整行丢内容；
- 资料编辑无改动直接返回，有改动才确认；
- 浏览设置“测试”不再隐式应用，或名称明确为“应用并测试”；
- 翻译凭据清除同步 UI，成功/失败/处理中可区分；
- 反向搜图区分取消当前搜索和离开页面；
- 手机/桌面授权 WebView 的 reload、新登录和返回动作名称与结果一致；
- 建立共享触觉入口（§5.6 的唯一实现），供 W4/W6/W7 消费。

这些修复必须先进入 `main`，后续触碰相同页面的工作包再基于新基线开展。

### W2 — discovery-query-context

拥有推荐、排行、新作、搜索输入/结果和反向搜图任务头：

- 发现页标签保证最低可读性，刷新反馈靠近当前内容；
- 排行明确内容类型与榜单模式，插画/小说共享同一套点击/拖动切换规则；排名变体由 W6 的对象组件提供并完成排行页接入，本包不自建条目组件；
- 新作范围与类型持续可见；重复点击当前标签固定为回到顶部快捷方式（见 §5.1），不再承载展开入口；
- 搜索共享可编辑查询头，类型、筛选摘要、清除与空结果修改条件始终可达；
- 建议项区分“填入”与“立即搜索”；
- 反向搜图在准备、进度、失败、空结果、原生/WebView 结果间保留图片、引擎和状态上下文。

### W3 — profile-bookmark-continuity

拥有作者页、收藏标签和资料编辑的连续上下文：

- 展开/收起状态保留返回、分享、更多和关注/编辑的等价路径，不出现可见但不可点；
- 作品类型持续可见，自己的主页可以更紧凑但不改变导航结构；
- 可导航统计带标签并真正导航；社交链接主操作打开、次操作复制；
- 分享默认路径与作品分享一致，复制链接独立；
- 公开/私密范围从作者页传入标签页和标签 feed；增加本地过滤与明确分页状态；
- 资料编辑固定保存入口，并用头像/背景各自真实预览形态。

W1 先落地资料编辑的返回判断；W3 在该契约上完成布局，不重复修改判定规则。

### W4 — artwork-viewer-series-flow

拥有插画/漫画详情、全屏查看器、动图和系列：

- 手机长漫画在首图附近可见标题、作者、页数与核心动作，并能直达完整信息/评论；桌面保持双栏等价命名；
- 普通下载从可见入口进入，只有批量页选择才进入带标题、计数、完成和取消的显式模式；
- 标签搜索/复制/屏蔽使用直接菜单，批量屏蔽若保留必须显式；
- 查看器实现 chrome 显隐、双击常用倍率、适应屏幕、页码选择、保存/分享/信息、空状态及键鼠等价操作；
- 动图保留媒体专属播放方式，把保存能力和准备/导出/失败状态放进一致入口；
- 系列区分更新游标和阅读进度，以数据源真实顺序能力支持开始/继续阅读和章节身份。

### W5 — novel-reader-parity

在 W1 的返回/恢复修复上抽取在线和本地小说共用的完整阅读舞台：

- 顶部返回/标题/更多、正文布局、底部目录/可操作进度/排版设置遵循一套状态机；
- 在线能力增量为收藏、分享、作者、评论；本地能力增量为文件信息；
- 字号、背景、翻页和恢复位置规则一致；桌面宽屏阅读正文按 §5.5 行长限宽接入；
- 进度跳转必须可操作、可取消且不把“打开信息”记作已阅读；
- 现有 NovelReader 内核优先复用，不创建平行阅读器。

### W6 — entity-management-consistency

拥有对象基础组件与任务型管理页面：

- 以一套小说条目支持 compact/regular 及排名、字数、进度等命名变体，排名/进度变体的排行页等调用点接入也归本包；
- 插画卡片只统一徽标角色，不统一图片裁切；
- 推荐/排行/搜索/新作在消费共享对象组件时保留自己的列表任务；
- 历史按日期/类型帮助找回内容，删除进入明确管理动作；
- 稍后再看提供移除和撤销，不扩成另一套收藏；
- 追更区分查看更新、打开目录和继续阅读；
- 本地书库主操作是继续阅读，删除进入更多；
- 下载组/子任务形成父子层级，暂停/失败/完成/取消使用一致动作映射，下载提交反馈可直达任务页；
- 管理列表按 §5.5 保持信息与动作聚合，限宽由本包按文件所有权接入。

### W7 — comment-input-state

拥有回复页和共享评论输入器：

- 根评论与回复进入同一滚动语义，或使用可折叠摘要；
- 回复目标由引用条持续表达，点击回复主动聚焦；
- 明确发送成功后回复目标是清除还是保留，并用测试固定；
- 输入状态严格为 none/keyboard/emoji/stamp 四选一，返回先关闭当前面板；
- 网格按可用宽度与最小点击区决定列数；插入后恢复正确焦点；
- 发送中可见，失败继续保留草稿。

### W8 — settings-form-semantics

拥有设置根页与配置/诊断页面，不包含下载任务管理 UI（归 W6）：

- 根页显示关键当前值，内容入口和配置入口归属清楚；
- 主题/语言保留简单单选，不扩成展示型页面；
- 日常浏览偏好优先，图源/网络配置归组；
- 翻译、账号、下载命名、保存位置、屏蔽、历史、网络高级设置区分即时值、草稿、应用中、成功、失败和重置；
- 保存位置主视图展示人类可理解名称，技术 URI 下沉；
- 备份先选合并/覆盖策略，再用同一确认层级执行；
- 仓库链接可打开/复制，更新错误按可行动原因区分；
- 落地共享表单/弹层与内容限宽契约（§5.5 的实现载体），并产出动作术语表（§5.7）供全包消费；
- 网络诊断先摘要后细节；帧探针录制生命周期与控制页分离。

### W9 — onboarding-auth-content-layout

拥有引导、登录、授权 WebView、Spotlight 文章与 sheet/dialog 语义对齐（表单/弹层限宽契约由 W8 建立）：

- 引导页共用可滚动、有限宽度、稳定下一步区域的 shell；
- 登录主动作始终存在，帮助和剪贴板导入是次级内容；
- W1 修正 WebView 动作后，两端共享错误层级与布局；
- Spotlight 文章使用受控行长、可选择正文、分享/打开原文；
- 即时设置弹层无需确认，草稿弹层有固定操作区并在失败时保留内容；
- 手机 bottom sheet 与宽屏 dialog 共享信息顺序/语义而非强求同一位置；
- 本包只接入自己拥有的页面（引导/登录/WebView/Spotlight）；阅读器归 W5、管理列表归 W6，表单/弹层限宽契约由 W8 提供，本包不重新定义。

### W10 — motion-integration-acceptance

最后验证而非先铺动画：

- 同级分类点击/拖动过程一致；
- 作者头部仅改变布局，不改变可达动作；
- 查询信息在输入/结果间连续；
- feed → detail → viewer 只有一条主要空间连续性；
- 表单/键盘动画不移动正在操作的主控件；
- loading 动效不延迟真实内容；
- reduced motion 只去装饰性位移/缩放，不移除反馈或动图内容行为；
- #48 SnackBar 与既有 MotionTokens 继续作为共享来源，不建立第二套常量。

## 5. 跨工作包契约

### 5.1 QueryContext

搜索、新作、排行、作者作品和收藏路径都需要可见上下文，但不强制共用一个业务模型。最小 UI 契约包含：

- 主范围/内容类型；
- 细分模式或筛选摘要；
- 修改与清除入口；
- 返回后恢复规则；
- loading/error/empty 时仍保留的上下文；
- 恢复等级：区分内存恢复（PageStorage）、路由 durable 值恢复与进程死亡后恢复，叶子必须声明每层覆盖范围，口径与 spec 的 Route Restoration Contract 对齐；
- 重复点击当前分类/标签固定为“回到顶部”（不附带刷新；刷新已有下拉手势），不得承载无其他入口的功能。

### 5.2 ObjectPresentation

共享对象组件只拥有识别与基础动作：封面/头像、标题、作者、语义元信息、按压反馈、可访问标签。排名、日期、进度、更新状态是组合槽位或命名 variant；页面不复制基础组件来改变密度。

### 5.3 FormState

所有表单/弹层至少明确属于以下一种：

1. immediate：修改立即生效，失败回滚并可见；
2. draft：本地编辑，显式保存，离开时按 dirty 状态确认；
3. action：执行一次操作，有 idle/busy/success/error；
4. destructive：危险动作有对象、后果和确认边界。

不得在同一控件中不加说明地混合这些模式。

### 5.4 BackAndCancel

- 系统返回优先关闭临时层；
- 显式页面返回默认离开页面，除非按钮清楚标明关闭某层；
- cancel 只取消当前操作，不隐式离开更高层页面；
- reload、restart login、return to login 是三个不同动作；
- 丢弃草稿只在 dirty 时确认。

### 5.5 ResponsiveContent

宽屏目标由任务决定：feed 增列、detail 双栏、form/settings 限宽、article/reader 控制行长、management 保持信息和动作接近。断点优先复用现有 shell/theme 约定；叶子任务不得各自发明近似宽度常量。

页面限宽按文件所有权分发：各叶子接入自己拥有的页面（W5 阅读器、W6 管理列表、W9 Spotlight/表单外壳）；W8 只拥有共享表单/弹层基件与宽度常量，其他叶子不新建第二套断点常量。

### 5.6 FeedbackChannels

- 操作结果反馈统一走 #48 建立的共享 SnackBar 入口，叶子不得新增平行反馈通道。
- 触觉反馈按动作角色分级：选中/切换使用轻触级；进入管理模式、危险确认、保存/发送成功使用明确震动；普通列表点击不加触觉。
- 触觉是冗余通道：系统触感关闭或设备不支持时，所有反馈仍须视觉可辨。
- 共享触觉入口由 W1 建立为 `lib/app/` 下的单一薄封装（`HapticFeedback`），W4 下载/保存、W6 管理模式与删除/撤销、W7 发送终态消费；W10 验收无第二来源。

### 5.7 ActionTerminology

同一后果使用同一动词；本节动词规则随本规划冻结、阶段 0 即生效，所有叶子直接消费；W8 在设置/表单迁移中补全场景词表并回归，W10 按表核对：

- 即时生效与待保存分别用“应用”/“保存”，无改动返回不叫“取消”；
- 删除语义分级：“删除”不可恢复，“移除”针对列表条目，“解除屏蔽”针对屏蔽项，“取消”只终止当前操作、不离开页面；
- “重试”是重试同一操作，“重新打开/重新登录”是重建流程，“返回”只表示导航；
- 下载完成的查看动作统一为“查看”类动词，不与“打开页面”混用。

## 6. 状态与数据边界

- 本任务不改变 API、认证、网络或持久化业务语义；UI 只读取/表达现有状态。
- 若实现需要新增持久化字段（例如真实章节阅读进度），叶子任务必须单独说明 schema、迁移、默认值和回滚；不能把更新游标冒充阅读进度。
- 查询和表单的草稿状态应由拥有其生命周期的 controller/store 管理，不在多个 Widget 里复制。
- 异步动作保持现有可观察错误，不吞错或转换为空成功。
- 用户输入在失败时保留；成功后清理什么由 PRD 明确并由测试固定。

## 7. 验证设计

### 自动化层

- Widget/unit tests：动作后果、返回优先级、上下文传播、状态机、失败输入保留、对象 variant。
- Golden/layout tests：仅用于稳定宽度/字体场景，不用截图代替交互测试。
- 静态质量：叶子任务运行聚焦测试、`flutter analyze --no-pub`、适用全量测试、`git diff --check` 和 `task.py validate`。

### 运行时矩阵

- 宽度：320、390、600、840、1200dp；手机横屏。
- 文本：至少默认与 1.3x/系统大字号；覆盖中文、英文和一组长翻译。
- 输入：触摸、系统返回/预测返回、键盘 Tab/Enter/Escape、鼠标滚轮/点击。
- 辅助技术：至少一条屏幕阅读器代表路径（TalkBack / Windows Narrator，作者头部、查看器、评论输入器优先），焦点顺序可解释。
- 反馈：触觉开启与关闭下操作结果均可辨；长按、危险确认、模式切换使用 §5.6 约定级别。
- 动效：默认与 reduced motion。
- 状态：loading、content、refresh error、load-more error、empty、busy、failure/retry。

设备或桌面环境缺失时必须写“未验证”，不能以 Widget test 推断真机通过。

## 8. 风险与回滚

- 共享组件迁移可能造成大范围视觉回归：先添加有限 variant 与测试，再逐页面迁移，最后删除旧组件；删除必须由 owning leaf 明确覆盖。
- 查询/阅读状态提升可能改变生命周期：在叶子设计中画出 source of truth、恢复和销毁路径。
- 多工作包触碰同一页面：严格使用 W1 → domain work package → W10 顺序，后一个任务基于已合并 `main`。
- 路由、导航、主题、MotionTokens 和本地化是高冲突区：只做完成行为所需的最小修改，不进行顺便重构。
- 每个叶子独立 PR；回滚用 `git revert`，不重写历史。

## 9. 已决策与待后续确认

已决策：

- 采用路线图父任务，而非一个巨型实现 PR。
- 保留现有主题、导航、状态层和组件目录；复用优先。
- #48/#50 作为已合入前提，不重复实现。
- 按确定错误 → 领域收敛 → 动效集成的顺序推进。
- 排名变体及其排行页接入归 W6，W2 不依赖 W6 产物，消解 W2↔W6 循环依赖。
- 表单/弹层限宽契约由 W8 建立，W9 消费；其余限宽规则沿用 §5.5。
- 增补非 Astra 条目：触觉反馈分级、屏幕阅读器代表路径、re-tap 回顶约定、动作术语表、进程死亡恢复等级。
- 二轮复核修订：术语表 §5.7 种子随规划冻结（阶段 0 生效），W8 只补全不首产，避免 W1–W7 先改文案后返工；共享触觉入口归 W1；re-tap 固定为纯回顶不带刷新；页面限宽按文件所有权分发，W8 只提供共享基件与常量。
