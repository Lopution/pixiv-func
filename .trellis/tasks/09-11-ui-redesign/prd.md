# 全项目 UI 视觉与交互重构

## Goal

把 Pixiv-func 从“功能齐全但页面各自为政”收敛成一个作品优先、界面克制、操作明确、跨尺寸稳定的 Pixiv 客户端。重构覆盖视觉语言、信息架构、共享组件、页面状态、交互反馈和视觉验收；保持现有真实数据流、账号能力和下载/阅读能力不变。

## Background and confirmed facts

- 项目是 Flutter 3.47.x 应用，使用 Material 3/Cupertino、Riverpod、go_router 和现有共享 widgets；此前的 M3 基础、路由基础和设置行为改造不等于全局视觉一致性已经完成。
- 当前主题把多层 `surfaceContainer*` 映射得过于扁平，排版层级、次要文字对比度、卡片/按钮/加载态存在重复变体；推荐、搜索、历史等页面的图库列数和间距规则也不统一。
- 当前 shell 有 `推荐/排行/最新/搜索/设置` 五个分支；`MePage` 已承载 Pixiv 个人资料、收藏、关注、粉丝、作品等内容，而设置页同时混入账户卡片、账户管理和应用级选项。
- “我的”是一级个人内容/账户区域；“应用设置”是独立的应用级区域，不放在“我的”的账户菜单中。底栏采用 `推荐 · 排行 · 最新 · 搜索 · 我的`，`/settings` 通过 shell 级齿轮/应用菜单进入；宽屏时作为 NavigationRail/Drawer 的同级入口。保留 `/settings/...` 深链接兼容。
- 竞品只作为问题拆解和模式参考：官方 Pixiv 用于信息架构，Pixiv-Shaft 用于克制的视觉/交互原则，Pix-EzViewer 用于自适应导航，Google Photos/Pinterest 用于内容优先图库和个人内容组织；不复制其品牌资产。

## Scope

### In scope

- 建立全局 design tokens：颜色与明暗表面层级、排版阶梯、间距、圆角、边框/分隔、图标、动效和状态语义。
- 重构应用壳层与信息架构：五个一级目的地、独立应用设置入口、宽窄屏导航形态、分支返回/深链接/状态恢复。
- 以“推荐 → 作品详情 → 作者 → 我的/收藏”为第一条样板链路，统一图库、详情头部、作者摘要、操作栏、加载/空/错/受限状态，并让关键操作可见且有反馈。
- 将共享卡片、缩略图、标签、按钮、筛选/分段控件、分页加载、错误重试、空状态、对话框/底部面板等抽成可组合的稳定变体；页面保留真实 Riverpod 状态消费者，不以 mock 或空操作掩盖状态问题。
- 迁移主要用户页面：推荐、排行、最新、搜索、作品/动图详情、作者/我的、收藏/关注/历史、小说、评论、下载任务、登录/引导及相关原生承载页，使其遵循同一套 tokens 和交互约定。
- 建立响应式与可访问性约束：手机窄屏/横屏、平板、桌面宽屏；大字号、长标题、多语言、键盘焦点、语义标签、最小触控目标和减少动效偏好。
- 建立可重复的视觉验收矩阵：亮色/暗色、中文/英文/日文/俄文、320/390/600/840/1200dp 代表宽度，以及内容、加载、空、错误、受限、动图等关键状态；截图只作为证据，不替代行为测试。

### Out of scope

- 不更换 Flutter、Material 3、Riverpod 或路由框架，不修改 Pixiv API、OAuth/TLS、账号凭据、缓存、下载、Ugoira 播放和阅读位置等业务契约。
- 不重新定义已完成的设置业务语义或网络行为；本任务只调整其归属、入口、布局和表达。
- 不承诺本任务解决运行时性能指标；图片加载、分页和缓存优化仅在 UI 重构确实暴露回归时按现有契约修复。
- 不复制竞品商标、插画、色板或专有交互，也不借视觉重构顺手删除未确认的功能。

## Requirements

### R1 — 视觉系统

所有新旧页面必须使用同一套可追踪 tokens 和语义组件；层级、对比度、排版和密度应能解释其用途。页面若需要特例，必须记录为命名变体而不是局部魔法数。

### R2 — 应用壳层与信息架构

一级导航固定为 `推荐/排行/最新/搜索/我的`。`/settings` 是与“我的”平级的应用级入口；账户管理、收藏、关注、历史等个人内容留在“我的”上下文。窄屏、宽屏、深链接、返回、分支栈和路由恢复的语义保持一致。

### R3 — 样板链路与交互

推荐→详情→作者→我的/收藏链路必须展示统一的作品优先视觉语言。收藏、关注、更多、下载、翻页/重试等关键操作不能只依赖长按或重复点击；每个异步操作都有进行中、成功/失败和可恢复反馈。

样板链路的页面层级固定为：作品主视觉 → 作者与标题 → 收藏/下载/分享等主操作 → 标签与说明 → 评论/相关作品。作品流统一使用自然图片比例、统一间距、统一角标和统一元数据层级；详情页不再为不同页面族重新发明卡片和操作栏。

作者页保留沉浸式头像/头图的安静头部，但头像、用户名、关注按钮、作品/小说标签必须分层呈现，不能把信息压进头图。搜索页首屏必须先提供搜索框，再呈现筛选条件、历史搜索和趋势标签；趋势标签点击直接执行搜索，不把“长按”当作唯一入口。

### R4 — 共享组件和页面状态

图库/列表卡片、详情媒体区、作者摘要、操作栏、标签、筛选器、加载骨架、空/错/受限状态和反馈面板提供稳定 API 与有限变体；同类页面不再各自复制近似样式。组件必须连接真实状态源并保留错误可见性。

### R5 — 自适应与可访问性

布局基于约束和可用空间而不是设备型号猜测；列数、内容宽度、导航形态和操作密度在代表宽度下有明确规则。文本缩放、键盘/遥控焦点、语义标签、触控目标和 reduced-motion 行为可验证。

约 600dp 以下优先 `NavigationBar`；中等窗口切换 `NavigationRail`；宽屏允许“左侧作品流 + 右侧详情”的双栏，但不强行压缩卡片。分页、瀑布流和横屏布局必须共用同一列数/间距函数，禁止按页面分别猜测高度。

### R6 — 验收证据

为关键页面和状态维护视觉样例/截图矩阵，并把“自动检查通过”“人工视觉审阅”“真实设备验证”分开记录。不得仅凭 golden 或编译通过声称视觉完成。

## Acceptance Criteria

- [ ] 五个一级目的地和独立应用设置入口在手机与宽屏均可发现；`/settings/...` 深链接、返回、分支栈和状态恢复通过既有路由测试。
- [ ] 推荐→详情→作者→我的/收藏样板链路在亮/暗主题和至少两种语言下共享 tokens、卡片/操作栏/状态组件，关键操作可见并有异步反馈。
- [ ] 样板链路符合固定层级；图库保持自然比例，作者页信息分层，搜索页首屏包含搜索框/筛选/历史/趋势且趋势标签可直接搜索。
- [ ] 主要页面完成迁移清单；每个页面的局部特例都有命名变体或记录，不再出现无法解释的重复卡片/按钮/加载样式。
- [ ] 320、390、600、840、1200dp 代表宽度及横屏场景无溢出、遮挡或不可达操作；大字号和长标题仍保持可读与可操作。
- [ ] 关键控件具备语义标签、可见焦点/键盘路径和足够触控尺寸；减少动效偏好下不依赖动画才能理解状态。
- [ ] 视觉矩阵覆盖亮/暗、中文/英文/日文/俄文、内容/加载/空/错误/受限/Ugoira 状态，并保留可复查的截图或 golden 证据。
- [ ] `dart format --set-exit-if-changed .`、`flutter analyze --no-pub`、相关聚焦测试和全量测试按仓库规范执行；`git diff --check` 干净。未能执行的设备/视觉检查必须明确列出。

## Notes

- 本任务是复杂、多页面重构，进入实现前还需要 `design.md`（组件/路由/状态边界）和 `implement.md`（可独立验证的阶段与提交边界）。
- 建议先完成 R1/R2 和样板链路，再按页面族迁移，最后补齐视觉矩阵与设备验证；阶段之间的依赖必须写进实现计划。
- 实现前需由用户确认全局视觉原则和第一条样板链路，避免把“导航已拍板”误解为“所有视觉细节已授权”。

## Confirmed decision

用户已确认将“作品优先、安静表面、操作可见、响应式图库”作为全局视觉原则，并以“推荐→详情→作者→我的/收藏”作为第一条验收样板链路。其他页面按实现计划在样板链路稳定后分族迁移；该决策不改变现有业务/API 契约。
