# 审查开源 Pixiv App 并优化 Replica v1 任务规划

## Goal

基于当前仍可核验的一手开源源码，系统审查 Pixiv Func Replica v1 的 17 个直接子任务及其实现叶子，找出能够提升架构一致性、真实可用性、失败恢复、性能、Android 集成和可验证性的方案，并把经过证据支持的改进落实到仍有效的 Trellis 规划中；其中“中国大陆用户无需外部代理/VPN仍能尽可能使用 Pixiv”提升为产品级目标与独立验收 Gate。

## Background and Confirmed Facts

- Replica v1 父任务为 `.trellis/tasks/08-26-pixiv-func-replica-v1`，当前有 17 个直接子任务，其中既包括实现叶子，也包括协调多个实现叶子的中间父任务。
- 用户明确授权检查全部 17 个直接子任务。
- 本次工作是源码调研与任务规划优化，不授权产品代码实现、远程发布或其他外部写入。
- 已完成并归档的任务是历史完成记录；其实现仍需审查，但不得通过改写归档计划把新建议伪装成当时已实现。需要补强的内容应进入父任务、尚未完成的任务或最终集成验收。
- 仍处于 `planning` 的任务可以在保留既有 Replica v1 产品边界的前提下直接优化其 `prd.md`、`design.md` 和 `implement.md`。
- 用户可见体验继续以 beta56 为事实来源；第三方开源项目只用于学习现代内部实现、边界处理和验证方法，不自动改变“体验冻结，内部重写”的产品决策。
- 用户新增明确产品目标：尽可能让中国大陆用户在不使用代理的情况下使用 Pixiv。仓库和第三方源码无法替用户决定“代理”是否包含 App 内部 Pixiv 域限定的透明 fallback，因此该定义保留为唯一阻塞问题。
- 当前 `08-26-ugoira-player-export` 已进入 `in_progress` 且工作树存在对应实现修改；本审查不触碰其产品代码，兼容网络只规划为该工作边界之后的下一项基础任务。

## Requirements

### R1. 候选项目选择

- 选择至少 3 个具有互补价值的开源 Pixiv 客户端，优先覆盖同技术栈 Flutter、Android 原生平台能力和成熟媒体/下载实现。
- 记录仓库 URL、固定 commit、许可证、近期活跃度与选择理由；不得只依据 README、star 数或二手文章评价。

### R2. 一手源码审查

- 对认证/账号、网络/分页、共享状态、搜索/社交/评论/小说、下载/Ugoira、历史/设置、Android intents/widgets/updater、Live 与发布验收等主题检查实际源码路径。
- 每项结论区分：源码明确证明、从结构作出的推断、未找到或不可复用的方案。
- 许可证不兼容或安全边界不符合本项目要求的代码只能作为设计参考，不得直接复制。

### R3. 全量任务映射

- 对 Replica v1 的 17 个直接子任务逐项给出：相关参考项目/源码、现有规划优点、缺口或风险、建议修改、落点与优先级。
- 对中间父任务继续下钻其实现叶子，保证建议能落到可执行的子任务或最终集成 Gate，而不是停留在泛泛建议。
- 已归档任务只记录实现后补强项；尚未完成任务可以直接更新计划。

### R4. 规划优化边界

- 保留 beta56 可见行为、严格 TLS、安全存储、有限内存/并发、真实失败可观察和逐任务审批等既有约束。
- 不引入隐藏 mock、关闭证书校验、硬编码凭据、无界缓存或未经核验的 Pixiv 常量。
- 新建议必须说明依赖、错误状态、取消/生命周期、验证方法以及必要的回滚点。
- 大陆可用性不能以关闭证书校验、改写 Host、第三方 API/图片反代、全局代理或单一网络样本换取。省 SNI 允许，但必须完成链验证与 SAN 核对；固定 IP 仅作兜底。必须分层（DNS / TCP / TLS / 真实请求）并分出口记录真实覆盖。

### R5. 持久化产物

- 在本任务 `research/` 下保存项目筛选、源码证据和 17 项审查矩阵。
- 更新 Replica v1 父任务的跨任务契约、执行顺序或验收矩阵；更新仍在 planning 的相关子任务规划。
- 对已归档任务发现的新缺口，写入仍开放的集成/发布任务或父任务，不改写历史完成声明。

### R6. 大陆无外部代理产品 Gate

- 更新父 PRD、架构、执行优先级、兼容网络 leaf 与最终集成任务，使目标覆盖 OAuth/WebView、API/refresh、图片缓存、下载/Ugoira 与后续 Widget headless，而不只是一个可选 API 开关。
- 从源码采用 host-scoped transport、failure taxonomy、TTL 与分出口分层诊断；明确拒绝第三方的关证书与反代实现。
- 采用 `Automatic` direct-first + `DirectOnly`：只有 eligible transport failure 才切换另一个严格候选。仅限 Pixiv 域的自动 fallback 属于允许的 App 内部传输，仍受 exact-host 与完整证书验证约束。
- 最终验收在系统 proxy/VPN 关闭、无外部代理 App 的 API 36 真机上记录 OAuth/API/pximg/download/WebView 的日期、运营商、IP family、Android/WebView 和实际 route；样本不足时不得作大陆普遍可用声明。

## Acceptance Criteria

- [ ] AC1：至少 3 个开源 Pixiv 客户端以固定 commit 完成源码级审查，并记录 URL、许可证、活跃度、选择理由和具体文件证据。
- [ ] AC2：17 个直接子任务全部出现在审查矩阵中；中间父任务的相关实现叶子有明确落点，不存在“已检查但无结论”的条目。
- [ ] AC3：每个改进建议都能追溯到第三方源码或当前仓库事实，并明确标注采用、暂缓或拒绝及其原因。
- [ ] AC4：仍在 planning 的相关任务规划已按审查结果更新；已归档任务未被改写为已包含新能力，其补强项进入父任务或开放的集成验收任务。
- [ ] AC5：Replica v1 的产品边界与安全约束没有因参考项目而漂移，许可证边界和禁止直接复制的内容有明确记录。
- [ ] AC6：运行 Trellis task validation、规划交叉引用检查和 `git diff --check`，结果真实记录；本次不声称产品代码已实现或设备/API 已验证。
- [ ] AC7：大陆无外部代理目标已写入父/compat leaf/integration 的 requirement、architecture、priority、真实网络矩阵和诚实声明边界；Q1 已由用户在 2026-08-27 确认，产品实现仍未启动并继续受自身 start approval 约束。

## Out of Scope

- 实现审查中提出的产品代码改动。
- 改变 beta56 用户可见体验或扩展 Replica v1 产品范围。
- 直接复制第三方 GPL/MIT 源码、资源、密钥、客户端身份或网络绕过方案。
- 发布、提交、推送或修改远程仓库状态。
- 实现网络兼容产品代码、搭建远程代理/中继，或承诺所有大陆网络 100% 可用。

## Open Questions

- Q1（已决议 2026-08-27，2026-08-29 修订）：“不使用代理”指无需安装或配置外部代理/VPN。范围收缩为**登录后使用**的四个 Pixiv 自有主机，首次注册/登录不在范围内。允许 direct-first + eligible failure 后仅限 Pixiv 域的 DoH 与严格连接；省 SNI 在自验证前提下允许，固定 IP 降为兜底，关闭证书校验继续拒绝。ECH 与 WebView loopback 已从方案中删除。
